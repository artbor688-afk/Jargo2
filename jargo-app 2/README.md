# Jargo — запуск с сохранением профиля по email

```
jargo-app/
  server.js         ← сервер: хранит профили в data/db.json по email
  package.json
  data/
    db.json          ← сама "база данных" (простой JSON-файл)
  public/
    index.html        ← весь фронтенд
```

## Почему так, а не через window.storage

`window.storage` (использовался раньше) — служебное хранилище только
внутри превью Claude, и, как ты заметил, иногда падает с
`Internal server error`. Сейчас вместо него — свой сервер с
файлом-базой на диске, который ты полностью контролируешь.

## Запуск

Нужен [Node.js](https://nodejs.org) версии 18+.

```bash
cd jargo-app
npm install
npm start
```

Открой **http://localhost:3000** — увидишь экран входа, введи любой
email (реальным он быть не обязан — проверка только на формат
`что-то@что-то.что-то`, письмо никуда не отправляется).

Всё, что делаешь дальше — прогресс по урокам, звёзды, жизни, купленные
аватары/аксессуары, никнейм — сохраняется в `data/db.json` под этим
email. Закрой вкладку, открой заново (или зайди с другого браузера,
если сервер доступен по сети) — введи тот же email и всё вернётся.

## Важно понимать про этот email-вход

Это **не настоящая авторизация** — нет пароля, нет проверки, что
письмо реально принадлежит тебе. Любой, кто введёт тот же email,
увидит тот же профиль. Для личного теста это нормально, но если
когда-нибудь захочешь открыть это для других людей — понадобится
настоящая проверка (magic-link на почту или пароль), это отдельная
доработка.

## Данные при деплое на хостинг

Если решишь выложить на Render/Railway (как обсуждали раньше для
звонка) — учти: у многих бесплатных тарифов файловая система
сбрасывается при каждом передеплое, и `data/db.json` вместе с ней.
Для реального продакшена данные лучше держать в настоящей базе
(Postgres, SQLite на постоянном диске и т.п.) — скажи, если нужно
такое усилить.
